# mlxc_parity.txt -- the parity ledger: every function of mlx-c 0.8.0, one line each, and what mlx-fortran does
# with it (doc/implementation_notes/planned/mlxf_mlxc_parity.md, decision 5). scripts/check_rules.py, rule
# `parity`, checks it against the headers and the library on every static gate.
#
#     <mlx-c name>  <class>  <Fortran name, or the reason>
#
# public     a public name of mlxf.f90 calls it (T%b: a binding or operator of the public type T)
# plumbing   the library calls it behind the handle model; no public name of its own
# internal   a C-level helper (vectors, maps, strings, closures, configs, setters) with no Fortran counterpart;
#            a wrapper that needs one calls it, and the line becomes plumbing
# excluded   not offered, with the reason
# pending N  to be wrapped in the plan's Phase N, under the planned Fortran name
#
# The count of pending lines may only shrink (PARITY_PENDING in check_rules.py, lowered in the same change).
